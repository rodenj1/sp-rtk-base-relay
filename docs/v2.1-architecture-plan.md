# SP-Base-Relay v2.1 Architecture Plan — Embeddable Relay Engine

## Overview

SP-Base-Relay v2.1 enhances the existing v2.0 multi-destination relay with features that make it **embeddable as a Python dependency** by external applications — specifically a planned GPS Base Station Web UI project.

The core purpose of sp-rtk-base-relay remains unchanged: **relay RTCM correction data from GPS input sources to multiple output destinations**. The v2.1 enhancements add:

1. A clean **RelayEngine facade API** for programmatic control
2. An **Event Bus** for real-time status notification
3. **Dynamic destination management** (hot add/remove/start/stop)
4. **Typed status snapshots** for rich runtime introspection

These enhancements make sp-rtk-base-relay usable in two modes:
- **Standalone mode** (unchanged): CLI + YAML config + systemd service
- **Embedded mode** (new): imported as a Python package by a host application

---

## Design Decisions (March 2026)

| ID | Decision | Rationale |
|---|---|---|
| DR-8 | In-process integration model | UI imports sp-rtk-base-relay directly; no IPC/HTTP needed |
| DR-9 | Programmatic config | UI builds Config/DestinationConfig objects in Python; no YAML file required for embedded use |
| DR-10 | Polling + Event Bus for status | Snapshot polling for current state + push events for discrete changes |
| DR-11 | Hot add/remove destinations | Add/remove destinations without stopping the hub or other destinations |
| DR-12 | Per-destination start/stop | Individual destinations can be stopped/started independently |
| DR-13 | RelayEngine facade | Single high-level API class for external consumers; hides internal complexity |
| DR-14 | Backward compatibility | main.py CLI, YAML config, Prometheus metrics all continue to work unchanged |

## v2.1 Architecture

### Standalone Mode (unchanged from v2.0)
```
config.yaml → ConfigManager → Config → SPBaseRelayService → BroadcastHub → Destinations
```

### Embedded Mode (new)
```
Host Application (e.g., GPS Web UI)
  │
  ├── Creates InputConfig + DestinationConfig objects programmatically
  │
  └── Uses RelayEngine API
        │
        ├── engine.start(destinations) → Creates BroadcastHub + starts relay
        ├── engine.add_destination(config) → Hot-adds a new destination
        ├── engine.stop_destination("rtk2go") → Pauses one destination
        ├── engine.get_status() → Returns typed RelayStatus snapshot
        ├── engine.subscribe_events() → Gets live RelayEvent stream
        └── engine.stop() → Stops everything, releases serial port
```

## Phase Plan

### Phase 1: Event Bus System
**New file**: `src/sp_rtk_base_relay/core/events.py`
**Test file**: `tests/unit/test_events.py`
**Estimated effort**: 1 session

#### Deliverables

1. **`RelayEvent` dataclass** (frozen, immutable)
   - `event_type: str` — dot-notation category (e.g., `"destination.connected"`)
   - `message: str` — human-readable description
   - `timestamp: float` — `time.time()` epoch
   - `payload: dict[str, Any]` — event-specific context (destination name, error, etc.)

2. **`EventSubscription` class**
   - Wraps a `queue.Queue[RelayEvent | None]` per subscriber
   - `get_event(timeout=1.0) -> RelayEvent | None` — non-blocking read
   - `close()` — unsubscribes and cleans up
   - Supports iteration (`__iter__` / `__next__`) for convenience

3. **`EventBus` class** (thread-safe)
   - `emit(event_type, message, **payload)` — creates event, pushes to all subscriber queues, appends to ring buffer
   - `subscribe() -> EventSubscription` — registers a new subscriber
   - `unsubscribe(sub)` — removes subscriber, sends poison pill
   - `get_recent(count=50) -> list[RelayEvent]` — returns last N events from ring buffer
   - Ring buffer: `collections.deque(maxlen=200)` — atomic append, no lock needed for reads
   - Subscriber list protected by `threading.Lock`

4. **Event type constants** — string constants for all event types:
   ```python
   # Hub events
   HUB_STARTED = "hub.started"
   HUB_STOPPED = "hub.stopped"

   # Input events
   INPUT_CONNECTED = "input.connected"
   INPUT_DISCONNECTED = "input.disconnected"
   INPUT_RECONNECTING = "input.reconnecting"
   INPUT_RECONNECTED = "input.reconnected"
   INPUT_NO_DATA_WARNING = "input.no_data_warning"

   # Destination events
   DESTINATION_STARTED = "destination.started"
   DESTINATION_STOPPED = "destination.stopped"
   DESTINATION_CONNECTED = "destination.connected"
   DESTINATION_DISCONNECTED = "destination.disconnected"
   DESTINATION_ERROR = "destination.error"
   DESTINATION_ADDED = "destination.added"
   DESTINATION_REMOVED = "destination.removed"

   # Engine events
   ENGINE_STARTED = "engine.started"
   ENGINE_STOPPED = "engine.stopped"
   ```

#### Tests (~80-100)
- EventBus: emit, subscribe, unsubscribe, multiple subscribers, ring buffer, get_recent
- EventSubscription: get_event with timeout, close, iteration
- Thread safety: concurrent emit + subscribe/unsubscribe
- Edge cases: emit with no subscribers, unsubscribe twice, subscribe after close

### Phase 4: RelayEngine Facade
**New file**: `src/sp_rtk_base_relay/engine.py`
**Test file**: `tests/unit/test_engine.py`
**Modified file**: `src/sp_rtk_base_relay/main.py` (refactored to use RelayEngine internally)
**Estimated effort**: 1.5 sessions

#### Deliverables

1. **`RelayEngine` class** — the primary API for embedded consumers:
   ```python
   class RelayEngine:
       """High-level relay engine for programmatic control.

       This is the recommended API for applications that embed
       sp-rtk-base-relay as a dependency. For standalone CLI usage,
       use `sp-rtk-base-relay --config config.yaml` which uses this
       engine internally.
       """

       def __init__(self, input_config: InputConfig) -> None:
           """Initialize engine with input source configuration.

           The engine is created in a stopped state. Call start() to begin relaying.

           Args:
               input_config: Input source configuration (serial, TCP, bluetooth, etc.)
           """

       # ── Lifecycle ──

       def start(self, destinations: list[DestinationConfig] | None = None) -> None:
           """Start the relay engine.

           Connects the input source, creates destinations from configs,
           starts the BroadcastHub, and begins relaying data.

           Args:
               destinations: Optional list of destination configs to start with.
                   If None, starts with no destinations (add them later).

           Raises:
               ServiceError: If engine is already running or input fails to connect.
           """

       def stop(self) -> None:
           """Stop the relay engine gracefully.

           Stops all destinations, disconnects input source, releases all resources.
           The engine can be started again after stopping.
           """

       @property
       def is_running(self) -> bool:
           """True if the engine is actively relaying data."""

       # ── Destination Management ──

       def add_destination(self, config: DestinationConfig) -> str:
           """Add a destination while running (hot-add).

           Creates the destination from config, starts its thread,
           and begins routing data to it.

           Args:
               config: Destination configuration.

           Returns:
               The destination name.

           Raises:
               ServiceError: If engine is not running.
               ConfigurationError: If config is invalid or name already exists.
           """

       def remove_destination(self, name: str) -> None:
           """Remove a destination (hot-remove).

           Stops the destination thread, disconnects from remote server,
           and removes it from the routing list.

           Args:
               name: Destination name to remove.

           Raises:
               ServiceError: If engine is not running.
               KeyError: If destination name not found.
           """

       def start_destination(self, name: str) -> None:
           """Start (resume) a specific destination.

           Re-enables data routing and starts the destination thread.

           Args:
               name: Destination name to start.
           """

       def stop_destination(self, name: str) -> None:
           """Stop (pause) a specific destination.

           Stops the destination thread and disconnects from remote server.
           Other destinations continue unaffected.

           Args:
               name: Destination name to stop.
           """

       def get_destination_names(self) -> list[str]:
           """Return names of all registered destinations."""

       # ── Status & Events ──

       def get_status(self) -> RelayStatus:
           """Get a typed snapshot of current relay state.

           Returns:
               Frozen RelayStatus dataclass with input, hub, and per-destination status.
           """

       def subscribe_events(self) -> EventSubscription:
           """Subscribe to real-time relay events.

           Returns:
               EventSubscription that yields RelayEvent objects.
               Call .close() when done.
           """

       def get_recent_events(self, count: int = 50) -> list[RelayEvent]:
           """Get recent events from the ring buffer.

           Args:
               count: Maximum number of events to return.

           Returns:
               List of recent RelayEvent objects (newest last).
           """

       @property
       def event_bus(self) -> EventBus:
           """Direct access to the event bus (advanced usage)."""
   ```

2. **Refactor `main.py`** — `SPBaseRelayService` uses `RelayEngine` internally:
   - `SPBaseRelayService.__init__` creates `RelayEngine(config.input)`
   - `SPBaseRelayService.start()` calls `engine.start(config.destinations)`
   - `SPBaseRelayService.stop()` calls `engine.stop()`
   - All existing CLI behavior unchanged
   - All existing `test_main.py` tests continue to pass

3. **Public `__init__.py` exports** — update package exports:

- Status: correct RelayStatus returned

## Risk Assessment

| Risk | Mitigation |
|---|---|
| Thread-safe destination list mutation | Lock-protected with copy-on-read in broadcast loop; minimal contention |
| Event bus memory in long-running service | Ring buffer with fixed maxlen (200 events); old events auto-evicted |
| Breaking existing tests | All new parameters are optional with default=None; existing constructors unchanged |
| Hot-remove race condition | remove_destination acquires lock, stops thread, then removes from list |
| RelayEngine complexity | Thin facade — delegates to BroadcastHub for all real work |
